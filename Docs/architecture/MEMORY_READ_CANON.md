# 메모리 읽기 정형

드라이버는 `signeddrv` IOCTL `0x222060`이다. 한 페이지(4KB)를 넘는 연속 읽기는 페이지마다 호출이 나뉜다. 같은 바이트를 필드마다 다시 읽는 호출을 없앤다. 호출 시각과 주기는 이 프로젝트의 결정 틱과 print_state 로스터 시계를 따른다.

맵 아이디는 `mgr → holder → subs → MapSubsystem(vft) → MapIdOff`만 쓴다. 서브시스템은 인덱스가 아니라 vft로 고른다.

## 매 틱 그대로 읽는 것

- 플레이어 HP, MP, SP, 레벨, 좌표, 서버 틱, 맵 아이디, 경험치, 상태 트리플
- print_state의 빠른 PRES (`0x48`)
- 버프 폴과 UI 대화 폴이 스냅샷을 요청받은 시각

결정 루프의 호출 간격은 바꾸지 않았다.

## 틱과 분리한 구조 스윕

`attacks_me`와 `contested_mobs`는 스냅샷이 매 틱 호출되어도, 엔티티 구조(액터 벡터 또는 셀맵, 액션 컴포넌트)는 print_state와 같은 시계로만 다시 읽는다.

- 직전 스윕 이후 100ms 미만이고, 플레이어 XY(`0x16DED30` / `0x16DED34`) 이동이 8타일 이하이면 저장된 JSON을 돌려준다.
- XY를 읽지 못하면 캐시를 쓰지 않고 스윕한다.
- 그 사이 틱의 강제 교전과 경합 필터는 최대 100ms 전의 목록을 본다.

print_state의 느린 명단은 원래 이 시계다. 그 위에 두 번째 캐시를 두지 않았다.

## 읽기 모양

한 번에 읽는 구간은 그 필드가 들어가게 잡고, 실패하면 예전처럼 필드마다 읽는다.

| 구간 | 한 번의 읽기 | 값 |
| --- | --- | --- |
| 플레이어 HUD | 베이스부터 SP(`0x110`)와 온라인 플래그까지, 상한 `0x200` | 기존 dword / byte |
| 좌표 | 틱과 XYZ가 붙어 있으면 틱 주소에서 `0x14` | tick, x, y, z |
| 맵 아이디 | `MapIdOff`와 pair가 +4이면 8바이트 | 첫째 dword. pair는 위치 확인용 |
| 캐릭터 상태 | 트리플이 끝나는 곳까지, 상한 `0x800` | `u8=b^k`, `c==((k+K_XOR)^~u8)`, 값 `u8-(k*K_MUL^K_XOR)` |
| 버프 맵 | end / vec / mask가 한 헤더(`0x80` 안)에 있을 때 | 세 포인터 |
| 버프 버킷 | 최대 256개 × 16바이트 | 노드 포인터 |
| 버프 노드 | `0x30` | rep, next |
| 버프 레코드 | `0x88` | refcount, strid, skill, dur, remain |
| PRES 바깥 표 | 엔티티 `+0x20` 힙에서 `0x180`. 칸 vft 또는 그 객체의 `+0x10` | 자식 포인터 0xA0 스캔은 하지 않는다 |
| UI 창 | 스냅샷당 창마다 `0x78` 한 번 | 열림은 `vis & VISMASK == VISOPEN` |
| 액션 테이블 | `+0x20`에서 16바이트 | begin, end |
| 액션 블록 | `0x140` | 아래 지문 |
| 셀 노드 | `0x28` | next, cx, cy, begin, end |
| 포인터 벡터 | 최대 512개 × 8바이트 | 액터 벡터는 짝수 슬롯 |

서브시스템 포인터는 vft로 캐시한다. 다음 조회는 캐시에 있으면 체인 전체를 다시 걷지 않는다. 같은 pid에 이미 붙어 있으면 PEB 모듈 워크를 건너뛴다. 프로세스나 베이스가 바뀌면 캐시를 비운다.

액터 그리드 포인터는 vft가 같을 때 재사용하고, 어긋나면 체인을 다시 걷는다.

## 액션 블록 지문

`0x140` 블록의 힙 포인터를 FNV(시작 `1469598103934665603`, 곱 `1099511628211`)로 접는다. 지문이 같고 힙 포인터가 하나 이상이면 슬롯 vft를 다시 읽지 않고 저장한 owner/tgt를 쓴다.

판정은 둘로 나눈다. 이름이 같아도 멈추는 슬롯이 다르다.

- `attacks_me`: AttackAction의 tgt가 내 guid인 첫 슬롯
- `strikes`와 `contested`의 `readAttack`: tgt가 있는 첫 슬롯

## 명단

액터 서브시스템의 평면 벡터(`+0x8A8` / `+0x8B0`, 쌍의 짝수 슬롯, 헤더 `0x50`)를 먼저 본다. 개수가 0이거나 청크 읽기가 실패하면 셀맵으로 간다. 벡터가 일부를 돌려주면 셀맵은 그 스윕에서 돌지 않는다. print_state와 같다. 셀맵에만 있는 엔티티는 그때 목록에 없다.

엔티티로 세는 vft, self 포인터, guid, 셀, 이름은 각 모듈의 기존 규칙이다.

## 출력 정합

같은 필드 이름이어도 모듈마다 값이 다를 수 있어, 이 프로젝트의 식을 유지한다.

- 영구 버프: `dur == 0xFFFFFFFF` 또는 `dur > 1000000`
- 버프·액터·맵 vft와 오프셋: `lc_reg_apply` / `offsets.json` / 각 settings JSON. 헤더의 컴파일 기본값은 레지스트리가 덮어쓴 뒤의 값을 본다
- 모니터 `entities`: 봇이 로드하는 DLL은 64KB 힙 창 재스캔을 시작하지 않는다. 키는 빈 배열이다. 농장 클릭과 사망 판정은 `print_state`의 `entities`다
- 모니터 버프: `BuffListBase`가 있으면 `g_base + offBuffList`. `apply_snapshot`이 이 배열을 버프 리스너보다 먼저 읽는다
- 단독 `realtime_monitor` exe는 `startDiscovery`를 스스로 호출한다
